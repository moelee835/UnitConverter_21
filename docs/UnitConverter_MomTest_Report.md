## 2. 질문·답변 기록

### Q1. 마지막 변환 경험

**질문:** meter, feet, yard를 **마지막으로 변환했을 때**가 언제였나요? 무엇을 변환했고, 어떤 도구를 썼나요?

**답변:**
- **2026-06-05** 아침
- **meter → yard** 변환 필요
- **`UnitConverter.py`** 사용 시도

---

### Q2. 가장 번거로웠던 순간

**질문:** 그때 **가장 번거로웠거나 시간이 걸린 순간**은 정확히 언제였나요?

**답변:**
- 단위명 **`meter`를 직접 타이핑**해야 함
- **`meters`로 오타** → **`Unknown unit`** 출력

---

### Q3. 실수 인지 시점·추가 소요 시간

**질문:** 오류를 **언제** 알아챘나요? **몇 분** 더 썼나요?

**답변:**
- **출력을 본 뒤** 인지
- 재시도까지 **약 5분** 추가 소요

---

### Q4. 다중 단위 vs 선택 출력

**질문:** 한 값을 **여러 단위로 동시에** 확인해야 한 적이 있나요? 각각 따로 계산했나요, 한 번에 봤나요?

**답변:**
- **자주** 발생
- meter·feet·yard **전부 출력할 필요 없음**
- **원하는 단위만 선택** 출력 필요
- 당일 사례: **meter → yard**만 필요 (해외 발신용 메일 작성)

---

### Q5. 변환 계수 확인 방법

**질문:** 변환 계수를 **어디서** 확인했나요? **몇 분** 걸렸나요?

**답변:**
- **프로그램 출력을 그대로 신뢰**

## 4. 진짜 문제 (Problem Statement)

실무에서 **특정 단위 쌍**(예: meter→yard)만 필요할 때, CLI에 단위명을 **정확히 타이핑**해야 한다. **`meters` 같은 오타**는 Unknown unit으로 실패하고, 사용자는 **출력을 본 뒤**야 알아채 **약 5분**을 다시 쓴다. 프로그램은 **세 단위를 모두** 출력하지만, 실제 필요는 **선택한 목표 단위 한 줄**인 경우가 **자주** 있다.
